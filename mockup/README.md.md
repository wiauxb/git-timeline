# `README.md`

## Purpose
End-user documentation of the tool. Not developer docs (those live in doc comments).

## Sections it must contain

1. **One-line pitch** + a screenshot / asciinema of the two-pane UI.
2. **Install**
   * `cargo install --path .` (or `cargo install git-timeline` once published).
   * Make sure `~/.cargo/bin` is on `PATH`; then `git timeline <file>` works because
     git runs `git-timeline` from `PATH`.
   * Requirement: git ≥ 2.36.
3. **Usage**
   ```
   git timeline [OPTIONS] <PATH> [REVISION_RANGE]

   git timeline src/main.rs
   git timeline src/main.rs v1.0..main
   git timeline -L 40,80 src/main.rs
   git timeline --author alice --since "3 months ago" src/main.rs
   ```
   Note that `git timeline --help` opens git's man-page lookup; use `-h`.
4. **Screen layout** — ASCII diagram (same as `ui/mod.rs.md`).
5. **Views** — content, diff vs previous, diff vs marked (how to mark), blame.
6. **Key bindings** — full table (generated by hand from `app/keymap.rs`).
7. **Pseudo-entries** — what `Working tree` / `Staged` mean and when they appear.
8. **Actions** — copy hash (clipboard / OSC 52 over SSH), export, restore (what restore
   does and does not touch: only the working-tree file, never the index or HEAD).
9. **Environment** — `NO_COLOR`, `GIT_TIMELINE_THEME`, `GIT_TIMELINE_LOG` (debug log file).
10. **Limitations** — single files only, no `.gitattributes` filters on working tree,
    `--follow` heuristics (git's own), very large files shown without highlighting.
